# ゴルフ攻略（スマホ用アプリ）

ラウンド中に、残り距離・次に持つ番手・打数を1打ずつ記録するアプリです。
PWA（ホーム画面に置けて、電波のない場所でも開けるWebアプリ）として作っています。

- 公開先：https://tmine52.github.io/twinlakes-golf/
- 入っているコース：ツインレイクスCC、玉川CC（アプリの中で切り替え。コースは後から足せます）
- 今の版：`js/version.js` に書いてあります（画面のいちばん下にも出ます）
- 記録の保存先：スマホの中だけ（サーバーには送りません）

リポジトリの名前とURLは、最初のコース名（twinlakes-golf）のままです。
変えるとホーム画面のアイコンを置き直す必要があるため、そのままにしています。

## 2. よくやる直し方

### コースを足す
方法は2つあります。

- **アプリに貼り付ける（その場で足す。自分のスマホだけ）**
  「番手の距離」画面 →「コースを追加」に、コースデータ（JSON という書き方の文字）を貼り付けて「追加する」。
  形は、同じ欄の「今のコースをコピー」で取れるものと同じです。
- **最初から入れておく（誰のスマホでも使える）**
  `js/courses.js` の `COURSES` に、コースを1つ足します。書き方はファイルの先頭の説明と、今ある2コースが見本です。
  足したら、版を上げて（下）、テストを回して（4章）、公開します（5章）。

座標（緯度・経度）は、Googleマップの航空写真でその場所を右クリックすると出る数字です。
`gc`（グリーン中央）があると残り距離が、`tc`（ティー）もあるとホール図が出ます。
曲がったホールは、曲がり角に `wp`（通過点）を置くと、残り距離を道のりで測ります（`tc` があるホールだけ）。
角の内側へ大きく外れた球は、直線の距離になります（道のりを長く出しすぎないため）。

### レッスンの内容を反映する
`js/advice.js` を直します。

- `COACH`：番手ごとのコーチの教え
- `BASE_TOP3`・`BASE`：当日の3つと、基本
- `ADV`：番手別の使い方（1つ目がラフでの扱い、2つ目が使い方）
- `DEF`：番手と最初の距離。**ここを変えても、すでに使っているスマホの距離は変わりません**
  （スマホで直した距離を勝手に上書きしないため）。全員の距離を最初の値に戻したいときだけ、
  `js/core.js` の `CV` を1つ上げます。

コースごとの注意（「3番の池越えで使う」など）は、`js/courses.js` の `clubTips` に書きます。

### 版を上げる
`js/version.js` の `APP_VER` と `APP_DATE` の2か所だけを直します。
画面の表示も、保存係（`sw.js`）も、この値を読みます。
**何か1つでもファイルを直したら、必ず版を上げてください**（上げないと、スマホが古いファイルを使い続けます）。
上げ忘れは、GitHub の中で動く自動テスト（`version_bumped`）が見つけて知らせます。

スマホは「版が変わった」と分かった時点で、全部のファイルを取りこみ直します。そのため、
**アップロードは1回（1回の「Commit changes」）で全部入れてください。**
どうしても分けて入れるときは、`js/version.js` を**最後**に入れます（途中の中途半端な状態を、スマホが取りこまないようにするため）。
分けて入れると、まだ無いファイルをスマホが取りに行くことがあります。GitHub Pages は「無い」という返事も10分以上使い回すので、
そのあとファイルを入れても、しばらく届かないことがあります（2026-11-18 に実物で確認）。

### ファイルを足す
`js` フォルダにファイルを足したら、次の2か所にも名前を足します（入れ忘れは自動テストが見つけます）。

1. `index.html` の起動係の `FILES`（動かす順番）
2. `sw.js` の `FILES`（スマホに保存するファイル）

## 3. 記録について

- 記録は、スマホのブラウザの中（localStorage という保存場所）にあります。名前は `golf-kouryaku-v1`。
- v28 までは `twinlakes-v1` という名前でした。v29 を最初に開いたときに、中身を新しい名前へ**コピー**します
  （古いほうは消しません）。
- お試しモード中の記録は、別の名前（`golf-kouryaku-v1-demo`）に入り、終わると消えます。
- **スマホを替える・ブラウザのデータを消す前に、控えを取ってください。**
  「番手の距離」画面 →「記録の控え」→「控えをコピー」か「ファイルで保存」。
  戻すときは、同じ欄に貼り付けるかファイルを選んで「控えを読み込む」（2回押して確定）。
  履歴は今の内容と合わせ（同じラウンドが両方にあるときは、新しく保存したほうを残す）、
  番手の距離は控えの内容になり（控えに読み取れない行があるときは、番手は変えない）、
  追加したコースは控えの分を足します。
- ホールの画像（ツインレイクス）は、合言葉で開きます。**合言葉はこのリポジトリに書かないでください**
  （リポジトリは誰でも見られるため）。

## 4. テストを回す

- 目的：直したあと、今までの機能がこわれていないかを確かめる
- 実行する場所：このフォルダ（`index.html` がある場所）を開いた PowerShell か WSL
- 今の状態：Python（3.10以上）が入っていること。ブラウザの部品は最初の1回だけ入れる

最初の1回だけ（部品を入れる）：

```powershell
py -m pip install playwright            # 画面を自動で操作する部品を入れる（WSL では py を python3 に読みかえる）
py -m playwright install chromium       # テスト用のブラウザ（Chromium）を入れる。数分かかる
```

毎回（テストを回す）：

```powershell
py tests\run_tests.py                   # 全部のテスト。2〜3分。最後に「合格 ◯・失敗 0」と出れば合格
py tests\run_tests.py gps demo          # 名前に gps か demo を含むテストだけ（急ぐとき）
py tests\run_tests.py --list            # テストの名前と、何を確かめているかの一覧
```

ツインレイクスの画像を開くテストは、合言葉を渡したときだけ回ります（渡さなければ「省略」と出ます）。

```powershell
$env:IMG_PASS = "ここに合言葉"            # この PowerShell の窓の中だけで有効。ファイルには残らない
py tests\run_tests.py images            # 画像のテストだけ回す
```

テストは、画面を出さないブラウザでスマホ幅の画面を開き、ボタンを押して結果を確かめます。
確かめたときの部品の版は playwright 1.63.0 です（GitHub の中では、この版に決めて動かしています。
上げるときは `.github/workflows/deploy.yml` の数字を直します）。
位置情報は、にせものの緯度・経度を渡して再現しています。**スマホ実機での確認の代わりにはなりません**
（屋外でのGPSの誤差、ホーム画面のアイコンからの起動、通知などは実機で見てください）。

## 5. 公開

公開先は GitHub Pages（GitHub が、リポジトリのファイルをそのままWebサイトとして出す仕組み）です。

- 今の状態（2026-11-18 時点）：公開の方式は「main ブランチのファイルをそのまま出す」。
  ファイルをアップロードすると、1〜数分で公開されます（そのあと最長10分ほど、前の版が届くことがあります）。

### 方法A：ブラウザでアップロードする（今までどおり）

- 目的：直したファイルを公開する
- 実行する場所：Chrome などのブラウザ（GitHub に **tmine52** でログインした状態）
- 手順
  1. 先に、手元でテストを回す（4章）
  2. https://github.com/tmine52/twinlakes-golf を開く →「Add file」→「Upload files」
  3. このフォルダの**中身を全部**（`js`・`tests`・`tools`・`.github` のフォルダごと）、1回でドラッグして入れる
  4. 下の「Commit changes」を押す
  5. 10分ほど待ってから公開先を開き、画面のいちばん下の版が新しくなっていることを確かめる
     （前の版のままなら、もう数分おいて開き直す）

「Uploads are disabled」と出たら、別のアカウントでログインしています。右上のアイコンから tmine52 に切り替えます。

### 方法B：自動公開（テストに通ったときだけ公開する）

`.github/workflows/deploy.yml` が、その手順書です。main ブランチにファイルが入るたびに、
GitHub の中で自動テストを回し、**全部通ったときだけ**公開します。
失敗したときは公開されず、前の版がそのまま動き続けます。

この手順書は、GitHub の設定を切り替えるまでは**テストだけ**を回します（公開は今までどおりの仕組みに任せます）。
切り替える前に「GitHub の中でもテストが通るか」を見られるように、こうしています。

自動公開の準備（GitHub の画面で、最初の1回だけ。tmine52 でログインして行う）：

1. まず方法Aで、このフォルダをアップロードする（`.github` フォルダも入れる）。
   今までどおりの方式で公開され、同時に、GitHub の中でも自動テストが動きます。
2. リポジトリの「Actions」タブ →「テストして公開」を開き、**「自動テスト」が緑のチェック**になっていることを確かめる。
   このとき「公開」は灰色（動かしていない印）になります。
3. 緑になっていたら、「Settings」→「Pages」→「Build and deployment」の **Source を「GitHub Actions」に変える**。
4. 「Actions」タブ →「テストして公開」→「Run workflow」を押して1回動かし、「公開」まで緑になることと、
   公開先がいつもどおり開けることを確かめる。これで、次のアップロードからは「テストに通ったときだけ公開」になります。
5. （任意）画像のテストも回したいとき：「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で、
   名前 `IMG_PASS`、値に合言葉を入れる。ここに入れた値は、他の人からは見えません。

手順2で「自動テスト」が赤い×だったときは、3の切り替えをしないでください（今までどおり方法Aで公開できます）。
GitHub の中のコンピューターは手元より遅いことがあり、時間に関係するテストだけ落ちる場合があります
（そのため GitHub の中では、失敗した場面を1回だけ自動でやり直します。それでも落ちたら赤い×になります）。
そのときは、失敗したテストの名前をクロコ（Claude）に伝えてください。

元に戻すには、手順3の Source を「Deploy from a branch」（ブランチ `main`・フォルダ `/ (root)`）に戻します。

### スマホ側の更新のされ方

- アプリを開くと、裏で新しい版を探します。見つけたら全部のファイルを取りこみ、そろってから切り替えて、画面を1回読み直します。
- 電波が弱くて取りこみきれなかったときは、古い版のまま動きます（新旧が混ざることはありません）。
  v28 から v29 へ上げるときも同じです（しくみは「9. 起動のしくみ」）。
- GitHub Pages は、ファイルの写しを最長10分使い回します。そのため公開の直後は、ファイルによって前の版が届くことがありえます。
  そのときも、スマホは古い版のまま動き、次に開いたときに取りこみ直します。
  **公開してから10分ほど待って開くと、1回で新しい版になります。**
- **ラウンドの前日までに、電波のある場所（家の Wi-Fi など）でホーム画面のアイコンから1回開き、いちばん下の版を確かめてください。**
  そのあと機内モード（電波を切った状態）でも開けることを確かめておくと、当日あわてません。
- 記録（打数・履歴・番手の距離）は、版が上がっても消えません。

### 前の版に戻したいとき

GitHub でリポジトリを開き、「Commits」から戻したい時点を開いて、その時点のファイルをもう一度アップロードします。
記録の保存場所は、v28 までの名前（`twinlakes-v1`）も消さずに残してあるので、v28 に戻しても、
v29 に上げる前の記録はそのまま見えます（v29 で足した記録は、v28 からは見えません）。
もう一度 v29 に上げると、v29 で足した記録に戻ります。**戻している間に v28 で足した記録は、v29 には出てきません**
（消えてはおらず、古い保存場所に残っています。取り出したいときはクロコに相談してください）。

## 9. 起動のしくみと、v28 からの引っ越し

### 起動係（`index.html` の中）

`index.html` は、`js` フォルダのファイルを直接は読み込みません。代わりに、起動係が次の順で動きます。

1. `js` フォルダのファイルを**全部**取りに行く（もう保存係がスマホに保存していれば、そこから出てくる）
2. 全部そろったら、決まった順番で動かす
3. 1つでも取れなかったら、**何も動かさない**（新しいファイルと古いファイルが混ざって、画面が出なくなるのを防ぐ）

3 のとき、画面には「読み込めませんでした。電波のある場所で、もう一度開いてください」と出ます。記録は消えません。

### v28 からの引っ越し（`app.js`）

v28 までは、アプリ本体が `app.js` の1本でした。v29 で `js` フォルダに分けました。
v28 が入っているスマホは、v28 の保存係（電波が弱いと、スマホに残っているファイルで代わりをする作り）が動いています。
そのスマホで v29 を初めて開くときに電波が弱いと、新しいファイルの一部だけが届かないことがあります。

そこで、`app.js` には **v28 の本体をそのまま**置いてあります。起動係は、ファイルがそろわなかった（または6秒待ってもそろわない）ときに、
「前の版の記録があり、今の版がまだ1度も動いていないスマホ」に限って、スマホに残っている `app.js`（v28）で動かします。
つまり、**v29 が全部そろうまでは、v28 が今までどおり動き続けます。**

- v29 が1度でも動いたスマホでは、v28 では動かしません（記録が2か所に分かれるのを防ぐため）。
  同じ理由で、v29 は起動のたびに、v28 の保存係がスマホに残した「古い入口」（v28 の画面）を、今の画面に入れ替えます（`js/main.js` の `retireOldEntrances`）。
- 記録の引き継ぎ（前の保存場所から新しい保存場所へのコピー）をするのは、アプリ本体（`index.html`）の最初の起動だけです。
  「上達道場へ渡す」画面（`send.html`）は記録を読むだけで、引き継ぎも保存もしません（引き継ぎがまだなら、前の保存場所をそのまま読みます）。
- v29 の保存係がスマホに入ると、v28 の保存場所は消え、以後は保存係が「全部そろってから切り替える」を受け持ちます。
- 保存係は、取りこんだ `index.html` に起動係が入っていないとき（＝前の版の画面が届いたとき）は、取りこみをやめて、次に開いたときにやり直します。
  起動係の書き出しの `<script id="boot">` は、その目印です。**この書き方は変えないでください**（`sw.js` と `js/main.js` が見ています）。
- **`app.js` は直さないでください。** 自分のスマホが v29 以降になり、機内モードでも開けることを確かめたあとは、消してかまいません
  （消すときは、`index.html` の起動係の `useOld`・`canUseOld` と、`tests/run_tests.py` の `boot_all_or_nothing`・`transition_from_v28`・`stale_copy_guard` も直します）。
